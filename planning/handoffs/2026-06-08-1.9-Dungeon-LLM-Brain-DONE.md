### Integration point correction (handoff vs reality)

The handoff said to add `_integrated_tick()` to `main.py` and "replace the old
`agent_os.tick()` call." **`agent_os` is not ticked from `main.py` at all** — it is driven by
`AgentOS.cluster_tick()`, called from `controller/controller.py` and
`scheduler/room_cluster.py`. So instead of a parallel tick (which would double-drive the
NPCs), the integration lives **inside `_think()`** — the one method every driver already
calls. This means cluster-based, controller-based, and the legacy `tick()` paths all get the
LLM brain for free, with **no signature changes** and no duplicate tick loop. The
trust/stigmergy/event_bus deps are injected as attributes (set once in `main.py`), so
`_think()` stays a `(self, npc_id, name)` method.

### Two real bugs avoided

1. **`state_of_mind="cooperative"` would be silently coerced to `"confused"`.**
   `StateStore.update_brain` validates against `{focused, confused, panicked, resting,
   planning, blocked}`. The handoff's prompt offered `"cooperative"`, which is **not** in
   that set, so every cooperative agent would have been flipped to `confused` → triggering a
   spurious `seek_help` cascade. The prompt hint now only offers valid states.

2. **`StateStore.commit_tick()` mis-resolves the PK for `dungeon_npcs`.** It picks the PK
   column with `"npc_id" if "npc_id" in pk else "agent_id"` — testing the literal string
   against the UUID *value*, which is always false, so it tries `agent_id` (a column
   `dungeon_npcs` doesn't have) → `OperationalError`. (Buffered writes are also dropped
   entirely when the caller didn't `begin_tick`.) This is a **pre-existing StateStore bug**,
   not introduced here. To stay robust and make visible side effects immediate, the
   execution phase writes pos/health/stamina/last_decision via **direct `self.db.execute`**
   rather than the StateStore write-buffer. Flagging it as a separate StateStore fix — out of
   scope for 1.9.

### ⚠️ One deviation from the spec (necessary fix)

The spec (Step 1 + Step 6) assumes `schema.sql` is applied at runtime. **It is not** —
`storage/db.py::init_database` creates tables via SQLAlchemy `Base.metadata.create_all`
(ORM models in `storage/models.py`); `schema.sql` is a reference file only. So adding the
table to `schema.sql` alone would NOT create it.

**Fix:** in `main.py::init_db`, the `event_store` table (+ indexes) is created at runtime
with an idempotent `CREATE TABLE IF NOT EXISTS … / CREATE INDEX IF NOT EXISTS …`
(mirrors the existing `ensure_os_state_tables` / `ensure_quest_tables` pattern). The
`schema.sql` entry is kept for documentation/backward-compat as specified.

> **Suggestion for a follow-up (optional):** add an `EventStore` ORM model in
> `storage/models.py` so it's created by `create_all` like every other table, and drop the
> inline DDL. Left out of 1.1 to keep the change surface minimal.

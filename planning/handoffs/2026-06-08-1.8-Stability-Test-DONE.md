### ⚠️ The handoff code could not pass as written — five fixes were required

I verified the engine's actual behaviour empirically first, then corrected the test.
All deviations are documented in the test's module docstring too.

1. **`ESS_TOPICS` does not exist** in `ess_protocol` → the import line would raise on
   collection. Removed (also dropped the unused `TFTVerifier` / `MessageType` imports).

2. **`pair_memory` was rebuilt inside every round** → a TFT agent could never retaliate
   across rounds. Because defectors act *after* TFT agents within a round and memory was
   wiped each round, every TFT cooperated with every defector **forever**. Measured result
   of that bug: `TFT→Defector == 0.30 == TFT↔TFT` — **zero separation**, so the test would
   prove nothing (and likely report PARTIAL/FAIL). Fix: `pair_memory` now **persists across
   rounds**, giving real cross-round Tit-for-Tat. Now defectors collapse to ~0.

3. **The `tft_tft > 0.3` assertion is mathematically impossible** with the shipped 1.4
   TrustEngine. Forgiveness resets the score to `BASELINE_TRUST` (0.3) after 5 consecutive
   cooperations, so sustained mutual cooperation **pins** TFT↔TFT trust at exactly 0.3 — it
   never rises to the "~0.45" the handoff's expected-output predicted. I confirmed this with
   a standalone engine run (50 mutual cooperations → 0.3000). The ESS criterion is therefore
   **baseline-aware and separation-based**:
   - `TFT↔TFT ≥ baseline` (not destabilised below it), **and**
   - `TFT→Defector < 0.1` (defectors rejected), **and**
   - `separation ≥ 0.2` (TFT clearly distinguishes cooperators from defectors).
   This is the honest statement of collective stability for this engine.

4. **True injection at round 51.** The handoff seeded all agents from round 1 (no actual
   invasion event). Defectors are now inactive during rounds 1-50 and injected at 51, so the
   pre/post split and the "watch the invasion" narrative are real.

5. **`open(schema.sql)` without an encoding** crashes on Windows (cp1250 can't decode the
   file's UTF-8 box-drawing). Opened with `encoding="utf-8"`; also `sys.stdout.reconfigure`
   to UTF-8 so the emoji/arrow report doesn't crash on a non-UTF-8 console. (Both are
   no-ops on a UTF-8 platform / CI.)

### Honest interpretation

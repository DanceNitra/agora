### What was implemented

| File | Change |
|------|--------|
| `api/ess.py` | **NEW** — `APIRouter(prefix="/api/ess")` with 5 endpoints |
| `main.py` | `from agora.api import ess as ess_api` + `app.include_router(ess_api.router)` |

**Endpoints (all async, JSON in/out):**
- `POST /api/ess/commit` — records a commitment (event store) + returns trust state
- `POST /api/ess/interact` — trust + TFT interaction, returns score/interactions/provokability
- `GET  /api/ess/trust/{agent_id}` — all outgoing relationships, or pairwise via `?target_id=`
- `GET  /api/ess/evaluate/{agent_id}` — TFT score + components + provokability averaged across partners
- `GET  /api/ess/aggregates` — every event_store aggregate type with event/stream counts

### One deliberate deviation: the 1.5 dependency was dropped, not faked

The handoff listed **1.5 (Ed25519)** as a dependency and the `/commit` sample imported
`ESSMessage`, `MessageType`, `ESSMessage.hex_to_public_key`. **None of those exist yet**
(1.5 is still 🟡), so importing them would have made the whole router fail to load.

Since the handoff itself says *"Signing requires private key — for now, just record the
commitment,"* I implemented `/commit` to do exactly that: append a `commitment_created`
event and return trust state. No import of unbuilt 1.5 symbols. **1.6 has zero dependency
on 1.5** — when 1.5 lands, `/commit` can attach a real `trust_sig` in a one-line addition.

Other small fidelity fixes vs the sample:
- `/interact` now passes real `trust_before`/`trust_after` into `verifier.record_interaction`
  (the sample dropped them), so the TFT log + event stream carry the trust delta.
- `parse_body` also rejects empty-string/null values, not just missing keys.

### Verified against real engines (TrustEngine + TFTVerifier + EventStore, in-memory aiosqlite)

> Note: the handoff's curl flow assumes a live uvicorn. Starlette's `TestClient` spins
> its own event loop, which deadlocks a single shared aiosqlite connection — a test-harness
> artifact, not a code issue. So endpoints were driven directly as coroutines on one loop.

All pass:
1. `POST /commit` → `200 {status: committed}`, commitment event written
2. `POST /interact` (cooperate) → `200 {status: recorded}`, `interactions == 1`, provokability present
3. `GET /trust/alice` → relationship to bob; `?target_id=bob` → pairwise with decay
4. `GET /evaluate/alice` → `tft_score`, components, provokability average over partners
5. `GET /aggregates` → `{trust, tft, commitment}` with counts
6. validation → `400` on missing `outcome` and on `outcome` ∉ {cooperate, defect}

`py_compile` clean; `ess.router` imports and exposes all 5 routes.

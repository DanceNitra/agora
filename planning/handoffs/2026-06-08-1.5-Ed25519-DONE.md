### Implementation notes (deltas from the sample)

- **Correct import** used throughout:
  `from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey, Ed25519PublicKey`.
- **Full 64-byte signature** → 128 hex chars (no truncation).
- **`verify()` is real** — `public_key.verify(...)`, catches only `InvalidSignature`
  (plus `ValueError`/`TypeError` for malformed hex so it "never raises"), returns bool.
- Sign/verify share one private `_signed_data()` so they can never diverge; the signed
  body is `type:agent_id:json(payload, sort_keys=True):timestamp` — `sort_keys=True` makes
  it deterministic regardless of dict insertion order. `target_id` is routing metadata and
  is deliberately **not** in the signed body.
- `MessageType` is a `str` enum and `_signed_data()`/`to_dict()` emit the `.value`
  (`"commit"`, not `"MessageType.COMMIT"`), so the wire form is clean and stable.
- Added `hex_to_private_key()` (sample only had the public side) — needed for any future
  code that wants to load a stored private key and sign server-side.

### Note for 1.6 REST API

`/api/ess/commit` still does **not** attach a `trust_sig` — and that's correct: signing
needs the agent's **private** key, which (per this task's own rule) is **not** stored in
`agent_identities`. Server-side signing would require a private-key store / secrets
manager first. The public keys are now real, so signature **verification** of
agent-supplied messages is possible today; signing is a client-side concern.

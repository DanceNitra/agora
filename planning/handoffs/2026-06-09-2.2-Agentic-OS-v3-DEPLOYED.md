### The 5 bugs (all from the same root cause + one route issue)

**Root cause for #1–3:** the 8 v3 tables are created by SQLAlchemy `create_all`, whose
columns use Python-side `default=` — which does **not** create a DB-level `DEFAULT`. So any
raw `INSERT` that omits a NOT NULL column inserts NULL and fails. (The v3 DDL with proper
defaults runs at main.py:177, but `ensure_os_initialized` seeds at main.py:108 — *before* it,
and `create_all` already made the tables anyway, so the DDL defaults never apply.)

1. **`agent_relationships` seed → server CRASH on startup.** Plain INSERT omitted NOT NULL
   `rivalry/attraction/debt/conversations_count/history`. `NOT NULL constraint failed:
   agent_relationships.rivalry` killed the lifespan. → made the INSERT explicit.
2. **`agent_emotions` seed → 0 rows (silent).** `INSERT OR IGNORE` omitted NOT NULL
   `history`, `decay_rate` → every row silently dropped → `/emotions` 404, all emotions null.
   → explicit INSERT.
3. **`agent_lifecycles` seed → 0 rows (silent).** Omitted 6 NOT NULL columns
   (`total_decisions`, `total_vault_notes`, `total_conversations`, `legacy`,
   `life_goal_progress`, `peak_experience`). → explicit INSERT.
4. **Route collision.** `/emotions`, `/culture`, `/conflicts` (single-segment) were shadowed
   by the `@router.get("/{npc_name}")` catch-all defined first → all 404 ("NPC emotions not
   found"). → moved the bare catch-all to the **end** of the router so specific routes win.
   (Same lesson as my Phase 2.0 `/brain/...` namespacing.)
5. **`controller.py` `npc.get("role")` on a `sqlite3.Row`.** Rows have no `.get()`; this threw
   every tick (`[Controller] DB cluster error`), breaking the NPC cognitive cluster tick. Since
   `role` is in the SELECT, → `npc["role"]`.

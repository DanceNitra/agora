### Deviations (reality vs handoff — all verified first, as with the ESS tasks)

1. **`_agentic_os_cycle()` as a new main.py tick was NOT added.** Dungeon NPCs are driven
   by `AgentOS.cluster_tick()` (controller/scheduler), not a main.py NPC loop — same finding
   as 1.9. A parallel cycle would double-drive them. Instead: per-agent cognition (memory
   recall, mood, thought journal) lives **inside `_think`** (so every driver gets it), and the
   **collective** layers (brainstorm/decay/conversation/upgrade) run from `_brain_ecosystem_tick()`,
   gated on 20-tick boundaries and **backgrounded** (`asyncio.create_task`) so heavy LLM work
   never blocks the tick.
2. **BrainstormEngine bugs fixed:** undefined `cursor_for_topic` (→ fetch topic), missing
   `MemoryAgent` import, votes coerced to `int` defensively.
3. **API route collision avoided:** the existing `/{npc_name}` catch-all would shadow
   single-segment paths, so global endpoints are namespaced under `/brain/...` (collective,
   brainstorm, upgrades, emotional-state) and per-agent ones are 2-segment.
4. **Mood `state_of_mind` validity:** unchanged from 1.9 — prompt only offers states the
   StateStore accepts.

### ⚠️ Runtime requirement

Brainstorm / conversation / upgrade generation call `dungeon_agent_think` → OpenRouter.
The server needs a valid `openrouter_key` (config / env) for these to actually produce text;
without it they fail gracefully (caught, no crash), exactly like 1.9. The per-agent memory /
mood / journal layers work with or without the key.

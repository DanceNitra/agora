### One deliberate fix vs the handoff code

The handoff's `_latest_checkpoint` recomputed the checksum with
`json.dumps(json.loads(state), sort_keys=True)`, but `checkpoint()` hashed
`json.dumps(state)` **without** `sort_keys`. Those two strings differ, so **every**
checkpoint would have failed the checksum and silently forced a full replay — and the
handoff's own test 4 (`_latest_checkpoint(...) is not None` after prune) would have
failed.

Fix: both write and verify now hash the **exact stored `state` string** via a single
`_checksum()` helper. Corruption is still detected (verified — see test 5), but valid
checkpoints verify correctly.

Also routed all trust replay (full + incremental) through one `_apply_trust_event()`
so the snapshot path and the catch-up path can never drift, and made TFT incremental
replay recompute from a full stream (TFT scores are window/variance based, not additive).

### ⚠️ Same deviation as 1.1 (schema is not auto-applied)

`checkpoints` is a raw-SQL table (no ORM model, exactly like `event_store`). It is
created idempotently in `main.py::init_db` via `executescript`, so the running app
always has it; `schema.sql` carries the canonical definition for reference / fresh
raw-SQL setups.

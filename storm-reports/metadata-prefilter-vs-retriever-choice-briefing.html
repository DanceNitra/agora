Filter before you rank is a shipped IR lever, not a new agent-memory finding

The 60-second summary

Settled: "filter the candidate set on cheap metadata before you rank" is one of the oldest working patterns in information retrieval and is already shipped as a first-class primitive in every production agent-memory stack (mem0 requires an entity scope; LangChain / LlamaIndex ship self-query retrievers; every vector DB documents metadata filters). It is not a discovery.

Contested: whether cheap metadata filtering beats retriever choice as a general law. The literature bundles metadata/temporal structure with retrieval and rarely isolates it; the one paper that isolates it (Multi-Meta-RAG) does so on news QA, not agent memory. Our own LoCoMo speaker pre-filter (+0.146 recall@20, bigger than the hybrid-over-single-vector win) is a real but best-case data point — two speakers, the question names one, brute-force retrieval — and its generalization to many-entity data, predicted (noisy) extraction, and HNSW indexes is unproven.

Key findings — ranked by reliability

01

"Filter-before-rank" is textbook IR and already shipped everywhere — not novel

confidence 9/10
Supported by: Historian, Practitioner, Academic

Faceted / attribute-constrained retrieval is canonical (Hearst, CACM 2006). In agent memory it is a mandatory primitive: mem0 requires at least one of user_id/agent_id/run_id; LangChain's SelfQueryRetriever and LlamaIndex auto-retrieval use an LLM to split a query into a semantic part + a structured metadata filter applied before search; Pinecone/Weaviate/Chroma/pgvector all document metadata filters. Any framing of metadata filtering as a new result would be wrong.

02

No published work cleanly isolates cheap metadata filtering vs retriever choice on agent memory

confidence 8/10
Supported by: AcademicChallenged by: Practitioner (says operators already know)

LongMemEval (ICLR 2025) bundles time-aware indexing + query expansion (temporal recall +6.8–11.3%). Zep/Graphiti and Mem0 report large temporal/multi-hop gains but at the architecture level, not as an isolated metadata-filter variable. The one clean isolation is Multi-Meta-RAG — same retriever, only an LLM-extracted metadata DB filter added — but on MultiHop-RAG (news), not conversational agent memory. So an isolated effect-size on agent-memory data is a genuine (narrow) measurement gap.

03

Naive pre-filtering can crater HNSW recall; the real lever is filtered-ANN

confidence 8/10
Supported by: Practitioner

On approximate (HNSW) indexes, restrictive pre-filtering fragments the graph and drops recall — worst exactly when the filter value correlates with embedding clusters (the speaker/topic case). Qdrant's fix is filterable-HNSW (extra intra-category edges); pgvector added iterative index scans. Brute-force stores don't have this problem — which is why a measured "+recall from filtering" on a brute-force probe is an upper bound a naive HNSW deployment won't realize.

04

A cheap metadata filter can match or beat retriever-choice gains — where it applies

confidence 6/10
Supported by: Practitioner, EconomistChallenged by: Skeptic

Multi-Meta-RAG: metadata DB filtering lifted MultiHop-RAG accuracy 0.47→0.608 (PaLM, +25.6%) with the same retriever — a bigger move than typical embedder swaps. Our LoCoMo speaker pre-filter adds +0.146 recall@20 (0.583→0.729, 10/10 conversations, conv-level bootstrap CI [+0.124, +0.173]), vs the hybrid-over-single-vector win of +0.057. Both isolate the filter; both are on favorable data.

05

Our LoCoMo +0.146 is a best-case, not a general law

confidence 5/10
Supported by: Practitioner (real lever)Challenged by: Skeptic, Academic

LoCoMo dialogs have only two speakers and questions name one 89% of the time, so a speaker filter halves the pool using a label the benchmark hands you. On many-entity corpora, with predicted (noisy) extraction that hard-deletes gold on error, and on HNSW indexes, the lift should shrink and can go negative. (LoCoMo's audited answer-key/judge defects target answer-correctness scoring, not our judge-free evidence-turn recall — so they do not directly undercut this number, but the 2-speaker cardinality does.)

The hidden connection

The cheap structured lever repeatedly wins deployment while the fancier statistical ranker wins the benchmark headline — Boolean pre-filtering ran commercial retrieval for ~30 years, faceted search beat statistical clustering in the 2000s, BM25 out-survived dense retrievers out-of-domain in BEIR (2021), and RAG has now re-derived the metadata WHERE-clause. Each generation re-discovers "filter first." The real variable was never the ranker; it is who pays the metadata-curation cost. So our result is that 60-year pattern re-run on agent memory — an honest isolated measurement, not a new law.

Key assumption · the missing 6th lens

Every lens (and our probe) implicitly assumes retrieval is brute-force, where applying a filter is free. The missing lens is the index-structure engineer: on production ANN (HNSW), a pre-filter interacts with the graph and can hurt recall unless the DB does filtered-ANN. This flips the conclusion for anyone on a managed vector DB — and, conversely, means a brute-force store (like mnemo) is in the one regime where the measured filtering gain is safe to bank.

What to do — for an agent-memory / RAG engineer

  • Treat a cheap metadata/entity/time pre-filter as a first-class stage, not an afterthought — but apply it inside the ANN traversal (Qdrant filterable-HNSW, pgvector iterative scan), never as a naive pre/post filter on a plain HNSW index.
  • Do not present metadata filtering as a finding; it is standard. If you measure it, publish the isolated effect-size on agent memory — that is the only part not already in the literature.
  • When you quote a filtering win, state the selectivity and the extraction method: a gain from a gold 2-way label is not evidence for many-entity, predicted-extraction settings.
  • On a brute-force store (small corpora, mnemo-style), a metadata pre-filter is safe and cheap — ship it; the HNSW caveat doesn't apply.

Claim safety guide

Safe to assert

  • Metadata / attribute pre-filtering is textbook IR and shipped in every agent-memory stack (Hearst 2006; mem0 mandatory scoping; self-query retrievers).
  • BM25 is a robust strong baseline OOD (BEIR, NeurIPS 2021).
  • Naive pre-filtering degrades HNSW recall; filtered-ANN is the fix (Qdrant, pgvector).
  • Our LoCoMo speaker pre-filter = +0.146 recall@20 — with the best-case caveats.

Assert with caveat

  • Multi-Meta-RAG +25.6% (PaLM) from metadata filtering alone — preprint; GPT-4 endpoint is +7.9% not +26%.
  • LongMemEval time-aware gains (+6.8–11.3% temporal) — bundled, not an isolated filter.
  • "Cheap filtering beats retriever choice" — shown only on favorable benchmarks; unproven at low selectivity / noisy extraction.

Avoid / don't repeat

  • Mem0 "+29.6 temporal / +23.1 multi-hop" — not in the paper (blog figures; paper says +26% overall, +11% temporal, +7% multi-hop).
  • "We discovered metadata filtering helps" — it's textbook.
  • Crediting Penfield for the "filesystem 74%" baseline — that is Letta's.
  • Claiming our +0.146 generalizes to many-entity / predicted-extraction / HNSW.

Contested signal

Zep/Graphiti "+18.5% accuracy, −90% latency" is a vendor preprint and the +18.5% is against a context-stuffing baseline, not MemGPT — kept but demoted. Mem0's headline "+29.6/+23.1" figures are marketing, not in the arXiv paper — treated as false. LoCoMo's audited defects (6.4% answer-key errors; judge accepts 62.8% of adjacent-wrong answers) are real but concern answer-correctness scoring, not the gold-evidence-turn annotations our recall metric uses.

The frontier question

Does cheap metadata pre-filtering still beat retriever choice at LOW selectivity (many entities) with PREDICTED (noisy) extraction on a filtered-ANN index — or is its measured dominance an artifact of favorable benchmarks and brute-force retrieval?

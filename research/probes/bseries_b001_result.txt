    (not a framework test; embedder = REAL nomic-embed-text (nomic-embed-text))

store: 23 active memories = 3 preferences (session 1) + 20 episodic (sessions 2-4); 6 new-session queries (unrelated topics)

[similarity_only]  recall by query similarity (inspeximus hybrid RRF, strong baseline):
    mean pref_recall@3  = 0.222
    mean pref_recall@5  = 0.333
    mean pref_recall@10 = 0.333
    mean pref_recall@20 = 0.333
    per-query pref_recall@5 = [0.0, 1.0, 0.0, 0.33, 0.0, 0.67]
    -> 3/6 unrelated-topic queries surface ZERO of 3 preferences; it's a coin toss driven by incidental topical overlap, not reliable recall.

[recency_window]  inject most-recent W memories (query-independent):
    pref_recall(W=3 ) = 0.000
    pref_recall(W=5 ) = 0.000
    pref_recall(W=10) = 0.000

[typed_profile]  retrieve preferences BY TYPE (profile injection, query-independent):
    pref_recall = 1.000  (all 3 preferences, every query, fixed inject budget)

structural reason (orthogonality): mean cosine(query, preference) = 0.401  vs  mean cosine(query, best on-topic memory) = 0.789
    -> the preference sits WELL BELOW the on-topic memory (gap 0.39); with nomic's high anisotropic baseline, 0.40 is a low score - so a topical match outranks the preference whenever one exists.
precision cost: to reach the first preference, similarity must go to rank ~3.0, dragging in ~2.0 non-preference memories first.

Reading: B-001 is a retrieval-OBJECTIVE mismatch, not a storage loss. Query-similarity retrieval
ranks by topical relevance to the current query; a preference is causally load-bearing for STYLE
but topically orthogonal to the query's CONTENT (cosine to the query well below on-topic memory),
so whenever the query has real topical matches they fill the top-k and the preference is filtered
out - on half our unrelated-topic queries similarity surfaced 0 of 3 preferences (and it's a coin
toss, not a floor). Recency also fails - preferences are the oldest memories. A separate
type/profile channel (unconditional injection) is the substrate that gets B-001 right, at a fixed
inject-budget cost + a write-time 'this is a preference' classification. This is exactly what
production profile memory does (MemGPT/Letta core memory, mem0 user memory); we measure the cost
of NOT doing it, we did not invent it.
Scope: substrate only (not the agent's generated answer); recall = the necessary precondition for
preference application, not proof the model then applied it. Single fixture set / one embedder.

# REA: MetaHuman Audio Driven Animation (UE 5.8.4), how it works and where we can push it

Date 2026-11-08. Gate: licensed engine source read locally, read-only, purpose interop/learning. VERDICT PASS.
Source root: `UE_5.8/Engine/Plugins/MetaHuman/MetaHumanAnimator/Source/MetaHumanSpeech2Face`.

## SEEN
- Two neural models as NNE assets: `Content/Speech2Face/NNE_AudioDrivenAnimation_AudioEncoder.uasset`,
  `NNE_AudioDrivenAnimation_AnimationDecoder.uasset`; a `whisper_encoder.uasset` sits beside them
  [ZDROJ: plugin Content/Speech2Face listing].
- Audio encoder: input `[1, samples]`, output `[1, frames, 512]` at 100 fps
  [ZDROJ: Speech2FaceInternal.cpp:286-297; Speech2Face.h:38 AudioEncoderOutputFps = 100].
- Decoder inputs: audio features `[1, frames, 512]`, **mood index (one int per clip, -1 = AutoDetect)**,
  **mood intensity (one float per clip)** [ZDROJ: Speech2FaceInternal.cpp:327-359, 403-412].
- Decoder outputs three streams at 50 fps: face rig controls, blink controls, head-pose controls
  [ZDROJ: :364-378; Speech2FaceInternal.h:31 RigLogicPredictorOutputFps = 50]. Resampled to the output fps;
  blinks are ADDED on top of face controls [ZDROJ: :219-228].
- Mood intensity: UI clamps 0..1 (`ClampMax = 1.0`), C++ only checks `>= 0` [ZDROJ: AudioDrivenAnimationConfig.h:43-44;
  Speech2FaceInternal.cpp:271].
- Output controls: `FullFace` or `MouthOnly` (MouthOnly keeps only mouth raw controls) [ZDROJ:
  AudioDrivenAnimationConfig.h:29-32; SpeechToAnimNode.cpp:276-278].
- Head motion is generated by the model as its own stream and turned into a head transform
  [ZDROJ: SpeechToAnimNode.cpp:146-192].
- 13 moods incl. AutoDetect (enum seen from Python: ANGER, BOREDOM, CONFIDENCE, CONFUSION, DISGUST, EXCITEMENT,
  FEAR, HAPPINESS, NEUTRAL, PLAYFULNESS, SADNESS, SURPRISE, AUTO_DETECT).

## INFERRED [NAZOR]
- One mood for a whole clip is why emotion feels flat: the model cannot follow an emotional arc inside one solve.
  Solving each line separately with its own mood and cross-fading gives an arc.
- MouthOnly + our own upper-face layer (brows, eyes, smile curves) separates "accurate lips" from "acting".
- The exported AnimSequence is plain curves (260 CTRL_expressions_*), so lip closures, jaw range and blinks can be
  post-processed per curve without touching the model.
- Intensity above 1.0 may extrapolate emotion; only a test shows whether the Python setter clamps it.

## Measured 2026-11-08 (lever 1 + 2)
- A Sequencer skeletal-animation track on the built BP's Face does NOT drive it (mouth closed in every frame).
- Duplicating a level sequence drops the control-rig channels (copy: 0 channels, source: 37,615 keys). Export a fresh
  sequence and edit its keys in place (`ue_arc2.py`).
- Per-line mood blend + jaw x1.12, lipsTogether x1.3, blink x4 works in the render. Scaling the NEGATIVE blink values
  opens the eyes wide; scale only positive values. Visible difference to plain CONFIDENCE is small on stills.

- CORRECTION: control-rig key `frame_number` is in DISPLAY-rate frames (30 fps), not tick resolution (24000).
  The first "per-line mood" render used ticks, so every key fell before 0.02 s and the blend was pure CONFIDENCE.
  Fixed in `ue_arc2.py` / `ue_smile.py` (use `get_display_rate()`); v5 blends moods for real.
- Directed smile layer (`ue_smile.py`, additive cornerPull/dimple/cheekRaise/squint/brow with 0.3 s ramps) gives a
  clearly visible smile and Duchenne cheeks on the chosen line: `lipsync/depesa_spieva_rezia.mp4`.
